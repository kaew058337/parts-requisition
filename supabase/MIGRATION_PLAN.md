# แผนย้ายฐานข้อมูล Google Sheets → Supabase

ตัดสินใจแล้ว: ย้ายทั้งหมดครั้งเดียว · ไม่ต้องล็อกอิน · ตัดสลับช่วงสุดสัปดาห์
โปรเจกต์ Supabase: `xneiolwvblaoocsxfnsu`

## ระยะ 0 – เตรียม (ผู้ใช้)
- [ ] เชื่อมตัวเชื่อม Supabase กลับเข้าแชท (หรือรัน SQL เองใน SQL Editor)
- [ ] ส่ง Project URL + publishable (anon) key (ห้ามส่ง service_role key)
- [ ] ทำสำเนา Google Sheet ล่าสุดไว้ 1 ชุด
- [ ] จดตัวเลขอ้างอิงจากหน้าคลัง: จำนวน Part number / ล็อต / หน่วยรวม (ใช้ตรวจหลังนำเข้า)

## ระยะ 1 – โครงสร้างข้อมูล  (ไฟล์ `001_schema.sql` – ร่างแล้ว)
ตารางหลัก: requisitions, receipts, issues, returns_out, loans, counts, claims + รายชื่อ/วันหยุด/ผังที่เก็บ/ประวัติย้าย/รายการชุด/หลักฐานยกเลิก/บันทึกการใช้งาน
สิ่งที่ต่างจากชีทเดิม
- ลำดับ (seq) ใช้ sequence ของฐานข้อมูล → ไม่ซ้ำอีก (ปัญหาคัดลอกแถวหมดไป)
- ชีท รับ + รับคืนเข้าคลัง รวมเป็นตาราง receipts เดียว แยกด้วย source
- ยอดคลังไม่เก็บเป็นตาราง คำนวณจาก receipts − issues (ฟังก์ชัน/วิวในไฟล์ 002)
- anon ลบตรงๆ ไม่ได้ ยกเลิกต้องผ่านฟังก์ชัน (เก็บหลักฐานลง cancelled_records)

## ระยะ 2 – นำเข้าข้อมูล
1. ส่งออกแต่ละชีทเป็น CSV (หรือให้ผมอ่านผ่านตัวเชื่อม Google Sheets)
2. สคริปต์นำเข้าแปลงวันที่ (พ.ศ./ข้อความ) และคอลัมน์ ตามไฟล์ `003_import` (จะทำในระยะนี้)
3. ตรวจ: จำนวนแถวทุกตารางตรงกับชีท · ยอดคลังรวมต้อง = ตัวเลขอ้างอิงในระยะ 0 ทุก Part number

## ระยะ 3 – กฎธุรกิจเป็นฟังก์ชันฐานข้อมูล (`002_functions.sql`)
แทนที่ Code.gs ฝั่งเซิร์ฟเวอร์ (≈4,900 บรรทัด / API 59 ฟังก์ชัน) เรียงลำดับความสำคัญ
1. v_lots (คำนวณล็อต FIFO คงเหลือ) + ค้นหา
2. เบิก, รับ (เดี่ยว/หลายรายการ/รอเอกสาร TAI), จ่าย (เดี่ยว/หลายรายการ), ส่งคืน, คืนเข้าคลัง
3. ยกเลิก, ยืม, ตรวจนับ (รวมตัดจ่ายสารเคมี), ย้ายที่เก็บ, แก้ไขล็อต
4. S/N ประกัน เคลม, FLY AWAY KIT, TCI/TAI, KPI, รายงานประจำเดือน, สุขภาพระบบ
ทุกฟังก์ชันทำงานใน transaction เดียว (แทน LockService)

## ระยะ 4 – ต่อหน้าเว็บ
- เปลี่ยนชั้น `run()` ใน Index.html จาก google.script.run / POST /exec เป็น Supabase RPC
- โฮสต์เดิมบน Cloudflare Pages ใช้ต่อ
- งานที่ต้องย้ายนอกฐานข้อมูล: บอตไลน์ (webhook) → Supabase Edge Function · สำรองรายวัน → pg_dump/ตั้งเวลา · รายงาน Excel ยังสร้างฝั่งเบราว์เซอร์ได้

## ระยะ 5 – รันขนาน + ตัดสลับ (สุดสัปดาห์)
- ก่อนวันตัด: ทดลองใช้บน Supabase ด้วยข้อมูลสำเนา 1–2 สัปดาห์ เทียบผลกับชีท
- วันเสาร์ (ไม่มีใครบันทึก): ปิดการบันทึกในระบบเดิม → ส่งออกข้อมูลล่าสุด → นำเข้าใหม่ → ตรวจยอดตรงทุก Part → เปลี่ยนลิงก์ให้เจ้าหน้าที่
- วันอาทิตย์: ตรวจซ้ำ ระบบเดิมคงเป็นอ่านอย่างเดียวไว้ 1 เดือนเผื่อย้อนกลับ
- แผนถอย: ถ้าตรวจยอดไม่ตรง → ใช้ระบบ Apps Script เดิมต่อ (ไม่แตะข้อมูลในชีท)
